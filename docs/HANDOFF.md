# 새 Codex 대화를 위한 개발 인계

## 가장 먼저 읽을 내용

사용자는 **맥북 화면에 항상 보이는 Google 캘린더 위젯**을 만들고 있다. 브라우저 웹 앱이나 클릭해서 열어야만 보이는 메뉴바 팝오버가 목표가 아니다. 대화 기록은 `CONVERSATION.md`, 실행 절차는 루트 `README.md`를 참고한다.

최종 의도:

- 기본은 화면 맨 왼쪽의 좁고 항상 보이는 레일.
- 오전 9시~오후 9시의 하루 전체를 세로로 표시.
- 일정 색상 블록과 현재 시간 위치를 통해 남은 시간 및 회의 분포를 한눈에 파악.
- 마우스 오버 시 조금 확장되어 일정 제목과 조작 기능 표시.
- 클릭하여 오늘 일정 수정 또는 화상회의 참가.
- 일정이 다가오면 내용 말풍선이 잠깐 나타났다 사라짐.
- 왼쪽/오른쪽/위쪽/메뉴바 아래로 표시 위치 변경 가능.
- macOS 독립 앱과 시스템 알림 사용.

## 구현된 초기 버전

Electron + 순수 HTML/CSS/JavaScript. 런타임 의존성 없이 Electron 개발 의존성과 electron-builder를 사용한다.

- `desktop/main.cjs`: Electron 창, 메뉴바, 위치/폭 조절, 마우스 위치 감지, Google OAuth, API 호출, 암호화 토큰 저장, 일정 알림.
- `desktop/preload.cjs`: 제한된 IPC 브리지.
- `public/app.js`: 일정 렌더링, 겹침 배치, 편집 다이얼로그, 회의 참가, 말풍선.
- `public/calendar.js`: 날짜 범위·회의 URL·수정 payload 유틸리티.
- `public/style.css`, `public/index.html`: UI.
- `server.js`: 샘플 웹 UI 개발 서버. 실제 Google 연결은 데스크톱에서 제공.
- `test/calendar.test.js`: 날짜, 링크, 수정 검증 테스트 5개.

기본 레일 88px, hover 확장 420px. 프레임 없는 항상 위 창. 편집 다이얼로그가 열린 동안 자동 축소를 막는다. 말풍선은 8초 뒤 사라진다. macOS 모든 Space와 전체 화면 표시를 요청하도록 설정했다. 위치·항상 위·알림 활성화는 앱 userData의 preferences.json에 저장한다. 종료는 메뉴바 우클릭 메뉴에서 한다.

Google 기본 캘린더의 오늘 일정을 읽고 1분마다 갱신한다. Google OAuth 데스크톱 JSON을 파일 선택 또는 `GOOGLE_OAUTH_CREDENTIALS` 경로로 읽는다. 시스템 브라우저 + localhost 콜백 + PKCE 사용. 액세스/리프레시 토큰과 OAuth 클라이언트 정보는 Electron safeStorage로 암호화하여 userData에 보관한다. 렌더러로 토큰을 전달하지 않는다.

## 실제 검증 결과와 한계

클라우드 실행 환경은 Linux였다. 사용자 맥북에 연결되어 있지 않았다.

통과:

- npm 의존성 설치. 클라우드에서는 npm/Electron 캐시 경로와 프록시 설정이 필요했다.
- `npm test`: 5개 통과.
- main/preload/app JavaScript 문법 검사.
- 웹 UI HTTP 요청 검증.
- 외부 임시 linkedom 환경에서 DOM 통합 확인: 샘플 일정 4개 렌더링, 09–21시 레일, hover 상태 전환, 샘플 일정 수정, 알림 말풍선 표시. 이 임시 테스트 의존성은 프로젝트에 포함하지 않았다.
- `npm audit --omit=dev`: 취약점 0. 개발 의존성 전체가 안전하다는 의미는 아니다.

미검증:

- 실제 macOS 창 위치·hover resize·메뉴바·전체 화면 Space·Notification.
- 실제 Google 로그인/캘린더 읽기·쓰기. 사용자 OAuth JSON과 계정 연결이 아직 없다.
- macOS DMG 빌드, 서명, 공증.

Linux에서 `npm start`는 Electron Chromium SUID sandbox 설정 문제로 중단됐다. sandbox를 끄는 우회는 적용하지 않았다. 이것은 사용자 맥북에서도 실패한다는 증거는 아니다. 따라서 앱 전체 실행 검증 완료로 주장하면 안 된다.

현재 기능 제한:

- 기본 캘린더만 표시. 여러 캘린더 선택 기능 없음.
- 종일 일정은 표시만, 수정 미지원.
- 9–21시 바깥 일정은 확장 시 별도 버튼으로 접근.
- 색상은 현재 UI 일정 순서에 따른 팔레트이며 Google Calendar colorId 매핑은 미구현.
- 알림을 켜야 앱 알림이 시작됨. 명시된 popup 알림만 처리하며 캘린더 기본 알림(useDefault)은 미지원.
- 앱 종료/잠자기 중 알림은 보장하지 않음.
- 반복 일정 수정은 선택한 회차 대상으로 구현되었으나 실제 API 검증 필요.
- 대규모 일정·짧은 일정에서 압축 타임라인의 가독성/클릭 영역을 macOS에서 확인해야 함.
- hover 축소/확장으로 창 bounds가 바뀌므로 실제 커서 경계와 편집 창 동작을 우선 검증할 것.

### 옆방향 현재 시간 표시와 투명도 (2026-10-13)

삼각형을 레일의 안쪽을 향하는 옆방향 화살표로 변경하고 빨간 선을 3px로 강조했다. 오른쪽 레일은 왼쪽 방향으로, 왼쪽 레일은 오른쪽 방향으로 가리킨다. 설정 → 표시에 전체 투명도 0–65% 슬라이더 추가. 기본 0%(불투명도 1), IPC에서 불투명도 .35–1 검증 후 BrowserWindow.setOpacity로 전체 창에 적용하고 preferences에 저장한다.
